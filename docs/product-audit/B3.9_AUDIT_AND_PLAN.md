## 5. Security and authorization requirements

**Release blockers found by this audit (outside B3.9, owner placement required — never silently deferred):**
- **B39A-S01 (P0)** — password-reset and invite emails take their link origin from the request's `Origin`
  header (`auth.ts:226`, `invites.ts:150,312`); no Origin check exists in front of tRPC. A forged request
  mails the victim a genuine reset link pointing at another host → token theft → takeover of any account,
  including the super admin. Fix: links from `APP_BASE_URL` / an allow-list only; test. Pre-existing since
  2026-10-03. **Recommended: fix first, as its own owner-approved slice, before any B3.9 UI work.**
- **B36-R4 (P1, already YES)** — `messages.send` has no rate limit (verified). `invites.create` also has
  none (throwaway trial coaches can send unlimited Forma-branded invite emails — same slice as S01).

**B3.9 must keep (verified correct, do not redo):** `isAssignedCoachOf` on every client read/write;
author-private notes; per-coach check-ins and conversations; plan CAS; transfer CAS + in-transaction
re-check; the B3.8 default-deny P2 gate (no coach write is a query; no REST bypass); payments idempotency
and ownership; exact-match lookup.

**B3.9 requirements:** every new or changed coach write goes through the P2 gate and `useWriteGate`
(today ungated offline: `TransferRequestCard`, `AssignTemplate`, plan-version restore, `AddClientSheet`
invites, `OutgoingTransfers` cancel); every fixed race has a two-request concurrency test; no UI shows
another coach's data even where an API returns it.

8. **Truthful numbers.** One weekly-training rule across Summary ("3 of 3" distinct plan days) and Progress
